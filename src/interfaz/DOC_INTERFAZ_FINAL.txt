1. INTRODUCCIÓN
----------------------------------------------------------------
La capa de interfaz constituye la puerta de entrada del sistema.
Su responsabilidad es presentar la información al usuario, capturar
sus acciones y delegar la lógica de negocio a los controladores.
Está implementada con Tkinter, la biblioteca estándar de Python
para interfaces gráficas de escritorio.

Esta capa ha sido diseñada siguiendo los principios de la
Programación Orientada a Objetos (POO) y está completamente
alineada con el Diagrama de Clases de Diseño (DCD). Cada ventana
y cada panel reflejan fielmente los atributos y métodos definidos
en el diseño original.

ARCHIVOS QUE COMPONEN LA CAPA DE INTERFAZ:
- interfaz_base.py               -> Clase base (InterfazBase)
- interfaz_login.py              -> Ventana de inicio de sesión (InterfazLogin)
- interfaz_administrador.py      -> Panel del Administrador (InterfazAdministrador)
- interfaz_cliente.py            -> Panel del Cliente (InterfazCliente)
- interfaz_gestion_clientes.py   -> Pestaña de gestión de clientes
- interfaz_gestion_ejercicios.py -> Pestaña de gestión de ejercicios
- interfaz_gestion_rutinas.py    -> Pestaña de gestión de rutinas
- interfaz_registro_sesion.py    -> Formulario de registro de sesión
- interfaz_progreso.py           -> Pestaña de progreso (con parámetro META)

Todos estos archivos están disponibles en la carpeta `src/interfaz/`
y se consideran definitivos. Quedan pendientes de una revisión
final por parte de Juan y Eliam.

2. FUNDAMENTOS DE POO APLICADOS EN LA CAPA DE INTERFAZ
----------------------------------------------------------------
A continuación se detallan los principios fundamentales de la
Programación Orientada a Objetos y cómo se han aplicado en esta
capa.

2.1 ENCAPSULAMIENTO
----------------------------------------------------------------
El encapsulamiento oculta los detalles internos de una clase y
expone solo lo necesario a través de una interfaz pública. En esta
capa, los atributos de cada ventana son privados (prefijo `_`) y
se accede a ellos mediante propiedades `@property`.

APLICACIÓN EN EL CÓDIGO:
```python
class InterfazLogin(tk.Tk):
    def __init__(self, control_autenticacion):
        self._correo: str = ""
        self._contrasenia: str = ""
        self._control = control_autenticacion

    @property
    def correo(self) -> str:
        return self._correo

    @property
    def contrasenia(self) -> str:
        return self._contrasenia

Los atributos _correo, _contrasenia y _control solo son
accesibles a través de sus propiedades, garantizando que no se
modifiquen sin control.

2.2 ABSTRACCIÓN
----------------------------------------------------------------
La abstracción permite definir interfaces generales que ocultan los
detalles de implementación. En esta capa, InterfazBase actúa como
una clase base abstracta que proporciona métodos comunes (mostrar
mensajes, errores y confirmaciones) a todas las subclases.

APLICACIÓN EN EL CÓDIGO:
class InterfazBase(ttk.Frame):
    def mostrar_mensaje(self, mensaje: str) -> None:
        messagebox.showinfo("Informacion", mensaje)

    def mostrar_error(self, mensaje: str) -> None:
        messagebox.showerror("Error", mensaje)

    def confirmar_accion(self, mensaje: str) -> bool:
        return messagebox.askyesno("Confirmar", mensaje)

Las subclases (InterfazGestionClientes, InterfazProgreso, etc.)
heredan estos métodos sin necesidad de redefinirlos.

2.3 HERENCIA
----------------------------------------------------------------
La herencia permite reutilizar código entre clases relacionadas.
En esta capa, todas las pestañas que forman parte del panel de
administrador o cliente heredan de InterfazBase.

APLICACIÓN EN EL CÓDIGO:
class InterfazGestionClientes(InterfazBase):
    def __init__(self, master, control_clientes):
        super().__init__(master, controlador=control_clientes, padding=10)
        # ...

Esto evita la duplicación de código y garantiza que todas las
pestañas tengan la misma forma de mostrar mensajes y errores.

2.4 POLIMORFISMO
----------------------------------------------------------------
El polimorfismo permite que objetos de diferentes clases respondan
al mismo mensaje de forma distinta. En esta capa, todas las
subclases de InterfazBase responden a los mismos métodos
(mostrar_mensaje, mostrar_error, confirmar_accion), pero
cada una los usa en su propio contexto.

APLICACIÓN EN EL CÓDIGO:

    InterfazGestionClientes usa mostrar_mensaje para confirmar
    registros de clientes.

    InterfazGestionEjercicios usa mostrar_mensaje para confirmar
    creación de ejercicios.

    InterfazProgreso usa mostrar_error para reportar fallos al
    cargar el progreso.

2.5 PRINCIPIO DE RESPONSABILIDAD ÚNICA
----------------------------------------------------------------
Cada archivo tiene una responsabilidad única y bien definida:

    interfaz_login.py: solo maneja el inicio de sesión.

    interfaz_administrador.py: solo gestiona el panel del admin.

    interfaz_cliente.py: solo gestiona el panel del cliente.

    interfaz_gestion_clientes.py: solo gestiona el CRUD de clientes.

    interfaz_gestion_ejercicios.py: solo gestiona el CRUD de ejercicios.

    interfaz_gestion_rutinas.py: solo gestiona el CRUD de rutinas.

    interfaz_registro_sesion.py: solo registra sesiones.

    interfaz_progreso.py: solo muestra progreso y META.

2.6 INYECCIÓN DE DEPENDENCIAS
----------------------------------------------------------------
Cada interfaz recibe sus controladores como parámetros en el
constructor, en lugar de instanciarlos internamente. Esto facilita:

    Pruebas unitarias (se pueden pasar mocks).

    Desacoplamiento entre capas.

    Flexibilidad para cambiar implementaciones.

APLICACIÓN EN EL CÓDIGO:
class InterfazGestionClientes(InterfazBase):
    def __init__(self, master, control_clientes: ControlClientes):
        super().__init__(master, controlador=control_clientes)
        self._control_clientes = control_clientes

La interfaz no sabe cómo se construye ControlClientes, solo lo
recibe listo para usar.

2.7 TRAZABILIDAD CON EL DCD
----------------------------------------------------------------
Cada interfaz refleja fielmente los atributos y métodos del DCD,
incluso manteniendo los nombres en camelCase para los métodos
del diseño original.

EJEMPLO (InterfazAdministrador según DCD):

3. DESCRIPCIÓN DE CADA INTERFAZ
----------------------------------------------------------------

3.1 INTERFAZBASE (interfaz_base.py)
----------------------------------------------------------------
Propósito: Proporcionar métodos comunes a todas las interfaces.

Atributos:

    _controlador: Controlador asociado (opcional).

Métodos:

    mostrar_mensaje(mensaje): Muestra un mensaje informativo.

    mostrar_error(mensaje): Muestra un mensaje de error.

    confirmar_accion(mensaje): Solicita confirmación al usuario.

3.2 INTERFAZLOGIN (interfaz_login.py)
----------------------------------------------------------------
Propósito: Ventana de inicio de sesión del sistema.

Atributos (según DCD):

    _correo: Correo electrónico ingresado.

    _contrasenia: Contraseña ingresada.

    _control: Controlador de autenticación.

Métodos (según DCD):

    mostrarFormulario(): Construye el formulario de login.

    capturarCredenciales(): Captura los datos de los campos.

    iniciarSesion(): Ejecuta el proceso de autenticación.

3.3 INTERFAZADMINISTRADOR (interfaz_administrador.py)
----------------------------------------------------------------
Propósito: Panel principal del Administrador.

Atributos (según DCD):

    _administrador_actual: Administrador logueado.

    _control_clientes, _control_rutinas, _control_ejercicios.

Métodos (según DCD):

    mostrarMenuPrincipal(): Construye el menú.

    abrirGestionClientes(): Abre pestaña de clientes.

    abrirGestionRutinas(): Abre pestaña de rutinas.

    abrirGestionEjercicios(): Abre pestaña de ejercicios.

    cerrarSesion(): Cierra sesión y vuelve al login.

3.4 INTERFAZCLIENTE (interfaz_cliente.py)
----------------------------------------------------------------
Propósito: Panel principal del Cliente.

Atributos (según DCD):

    _cliente_actual: Cliente logueado.

    _control_rutinas, _control_sesiones, _control_progreso.

Métodos (según DCD):

    mostrarInicio(): Construye la ventana principal.

    consultarRutinaActiva(): Muestra la rutina activa.

    consultarProgreso(): Muestra el progreso.

    registrarSesion(): Abre el formulario de registro de sesión.

    cerrarSesion(): Cierra sesión y vuelve al login.

3.5 INTERFAZGESTIONCLIENTES (interfaz_gestion_clientes.py)
----------------------------------------------------------------

Propósito: Pestaña para gestionar clientes (CRUD).

Atributos (según DCD):

    _control_clientes: Controlador de clientes.

Métodos (según DCD):

    mostrarClientes(): Carga la lista de clientes.

    mostrarFormularioCliente(): Construye el formulario.

    registrarCliente(): Registra un nuevo cliente.

    editarCliente(): Edita el cliente seleccionado.

    eliminarCliente(): Elimina el cliente seleccionado.

    buscarCliente(): Busca por nombre o correo.

3.6 INTERFAZGESTIONEJERCICIOS (interfaz_gestion_ejercicios.py)
----------------------------------------------------------------

Propósito: Pestaña para gestionar ejercicios (CRUD).

Atributos (según DCD):

    _control_ejercicios: Controlador de ejercicios.

Métodos (según DCD):

    mostrarEjercicios(): Carga la lista de ejercicios.

    mostrarFormularioEjercicio(): Construye el formulario.

    crearEjercicio(): Crea un nuevo ejercicio.

    editarEjercicio(): Edita el ejercicio seleccionado.

    eliminarEjercicio(): Elimina el ejercicio seleccionado.

    buscarEjercicio(): Busca un ejercicio por nombre.

3.7 INTERFAZGESTIONRUTINAS (interfaz_gestion_rutinas.py)
----------------------------------------------------------------
Propósito: Pestaña para gestionar rutinas (CRUD + asignación).

Atributos (según DCD):

    _control_rutinas: Controlador de rutinas.

Métodos (según DCD):

    mostrarRutinas(): Carga la lista de rutinas.

    mostrarFormularioRutina(): Construye el formulario.

    crearRutina(): Crea una nueva rutina.

    editarRutina(): Edita la rutina seleccionada.

    eliminarRutina(): Elimina la rutina seleccionada.

    asignarRutina(): Asigna la rutina a un cliente.

3.8 INTERFAZREGISTROSESION (interfaz_registro_sesion.py)
----------------------------------------------------------------
Propósito: Formulario para registrar una nueva sesión.

Atributos (según DCD):

    _id_cliente: ID del cliente que registra la sesión.

Métodos (según DCD):

    mostrarFormularioSesion(): Construye el formulario.

    registrarSesion(): Registra la sesión en la BD.

    cancelarRegistro(): Limpia el formulario.

3.9 INTERFAZPROGRESO (interfaz_progreso.py)
----------------------------------------------------------------
Propósito: Pestaña de progreso con parámetro META.

Atributos (según DCD):

    _cliente: Cliente logueado.

Métodos (según DCD):

    mostrarProgresoMensual(): Muestra el progreso del mes.

    mostrarHistorial(): Muestra el historial completo.

    mostrarResumen(): Muestra el resumen de actividad.

Parámetro META:

    Se evalúa si el cliente alcanzó su objetivo (ej. bajar de peso).

    Se muestra con colores:

        Verde (META ALCANZADA): cuando el cliente logró su objetivo.

        Rojo (Meta no alcanzada): cuando aún no lo logra.

4. FLUJO DE TRABAJO TÍPICO
----------------------------------------------------------------
    El usuario abre la aplicación

    Se muestra InterfazLogin.

    El usuario ingresa credenciales y hace clic en "Iniciar Sesion".

    InterfazLogin.iniciarSesion() llama a
    ControlAutenticacion.iniciar_sesion(correo, contrasenia).

    Si las credenciales son válidas, se abre:

        InterfazAdministrador (si el usuario es admin).

        InterfazCliente (si el usuario es cliente).

    El usuario navega por las pestañas y realiza acciones.

    Cada acción delega en el controlador correspondiente.

    Los resultados se muestran al usuario mediante messagebox.

    El usuario cierra sesión y vuelve a InterfazLogin.
