1. INTRODUCCIÓN
----------------------------------------------------------------
La capa de dominio constituye el núcleo del sistema. Contiene las
entidades de negocio, las reglas fundamentales y la lógica que 
define el comportamiento del sistema, independientemente de la 
interfaz de usuario, la persistencia o los controladores.

Programación Orientada a Objetos (POO) y está alineada con el

2. TYPE HINTS Y LA LIBRERÍA `typing`
----------------------------------------------------------------
El type hinting (o anotación de tipos) es una característica de 
Python que permite indicar el tipo de dato esperado para los 
parámetros, el valor de retorno de las funciones y los atributos 
de las clases. No es obligatorio, pero mejora significativamente 
la legibilidad y el mantenimiento del código.

¿POR QUÉ USAR TYPE HINTS?
- Mejoran la legibilidad: cualquier persona que lea el código 
sabe qué tipo de datos espera cada método.
- Facilitan la detección de errores: herramientas como Pylance o 
mypy pueden advertir sobre inconsistencias de tipos antes de 
ejecutar el código.
- Mejoran el autocompletado en los IDEs (VS Code, PyCharm, etc.).
- Documentan el código de forma explícita y auto-contenida.

LA LIBRERÍA `typing` (incorporada desde Python 3.5):
Proporciona tipos genéricos para situaciones más complejas:
- `List[T]` → lista de elementos de tipo T.
- `Optional[T]` → valor que puede ser T o None.
- `Tuple[T, ...]` → tupla de elementos de tipo T.
- `Dict[K, V]` → diccionario con claves de tipo K y valores de tipo V.

EJEMPLO EN NUESTRO CÓDIGO:
```python
from typing import List, Optional

def agregar_ejercicio(self, ejercicio: EjercicioCardio) -> None:
    # Se espera un objeto EjercicioCardio y no retorna nada

@property
def ejercicios(self) -> Tuple[EjercicioCardio, ...]:
    # Retorna una tupla inmutable de ejercicios

En usuario.py:
def actualizar_datos_personales(
    self,
    nombre: str,
    apellido: str,
    correo: str,
    edad: int
) -> None:
    # Todos los parámetros tienen tipo definido

En cliente.py:

    contrasenia_hash: str,
    edad: int,

    objetivo: str,

    fecha_registro: Optional[date] = None,
    fecha_ingreso: Optional[date] = None,
) -> None:

Con esto, cualquier desarrollador que utilice estos métodos sabrá
exactamente qué datos proporcionar y qué esperar.

3. BUENAS PRACTICAS DE POO APLICADAS
----------------------------------------------------------------
A continuación se detallan los principios fundamentales de la POO
y cómo se han aplicado en la capa de dominio.

3.1 ENCAPSULAMIENTO
El encapsulamiento consiste en ocultar los detalles internos de una
clase y exponer solo lo necesario a través de una interfaz pública.
En Python, esto se logra con atributos privados (prefijo _) y
propiedades (@property).

APLICACIÓN EN EL CÓDIGO:

Todos los atributos de las clases son privados (ej. _nombre,
_peso, _ejercicios).

Se accede a ellos mediante propiedades getter y setter con
validaciones.

EJEMPLO (de usuario.py):
@property
def edad(self) -> int:
    return self._edad

@edad.setter
def edad(self, valor: int) -> None:
    if not isinstance(valor, int) or valor <= 0:
        raise ValueError("La edad debe ser un entero mayor que cero.")
    self._edad = valor

De esta forma, el estado interno de Usuario está protegido y no
puede ser modificado sin pasar por las validaciones.

3.2 ABSTRACCIÓN
La abstracción permite definir interfaces generales que ocultan los
detalles de implementación. En POO, las clases abstractas y los
métodos abstractos son las herramientas clave.

APLICACIÓN EN EL CÓDIGO:

Usuario es una clase abstracta (hereda de ABC) con el método
abstracto obtener_tipo_usuario().

Cliente y Administrador implementan ese método concreto.

Esto obliga a que cualquier subclase de Usuario defina su
comportamiento, garantizando que nunca se instancie una clase
incompleta.

EJEMPLO:
class Usuario(ABC):
    @abstractmethod
    def obtener_tipo_usuario(self) -> str:
        pass

class Cliente(Usuario):
    def obtener_tipo_usuario(self) -> str:
        return "cliente"

3.3 HERENCIA
La herencia permite crear nuevas clases a partir de otras,
reutilizando atributos y métodos. Es una relación "es-un".

APLICACIÓN EN EL CÓDIGO:

Cliente y Administrador heredan de Usuario.

Usuario concentra los atributos comunes (nombre, correo, edad,
etc.) y los métodos compartidos (cambiar contraseña, obtener
nombre completo).

Las subclases solo añaden o modifican lo específico.

Esto evita la duplicación de código y facilita los cambios: si se
modifica Usuario, todos los usuarios se actualizan automáticamente.

3.4 POLIMORFISMO
El polimorfismo permite que objetos de diferentes clases respondan
al mismo mensaje de forma distinta. En la práctica, se logra con
métodos que tienen el mismo nombre pero diferentes implementaciones.

APLICACIÓN EN EL CÓDIGO:

obtener_tipo_usuario() se define en Usuario como abstracto, y
se implementa en Cliente (retorna "cliente") y en
Administrador (retorna "administrador").

El controlador ControlAutenticacion puede usar este método sin
saber qué tipo de usuario es, confiando en que cada subclase
devolverá su propio valor.

3.5 COMPOSICION Y AGREGACION
Composición: relación fuerte donde el objeto hijo no puede existir
sin el padre (ej. Cliente → SesionEntrenamiento). En el DDL,
esto se refleja con ON DELETE CASCADE.

Agregación: relación débil donde el objeto hijo puede existir
independientemente (ej. Rutina → EjercicioCardio). En el DDL,
se refleja con ON DELETE SET NULL o tabla puente.

APLICACIÓN EN EL CÓDIGO:

Cliente contiene listas de AsignacionRutina, SesionEntrenamiento
y ProgresoMensual (composición).

Rutina contiene una lista de EjercicioCardio (agregación).
Los ejercicios pueden existir sin una rutina.

3.6 VALIDACION Y MANEJO DE EXCEPCIONES
Las clases validan los datos en los setters y en los constructores
para garantizar la integridad del estado del objeto. Esto evita que
un objeto entre en un estado inválido.

EJEMPLO(de rutina.py):
@duracion_semanas.setter
def duracion_semanas(self, valor: int) -> None:
    if not isinstance(valor, int) or valor <= 0:
        raise ValueError("La duración debe ser un entero mayor que cero.")
    self._duracion_semanas = valor

3.7 USO DE ENUMS
Los enums (NivelRutina, Intensidad, EstadoAsignacion) evitan
el uso de strings mágicos y garantizan que los valores sean siempre
válidos. Esto reduce errores y documenta las opciones posibles.

EJEMPLO (de ejercicio_cardio.py):
@intensidad.setter
def intensidad(self, valor: Intensidad) -> None:
    if not isinstance(valor, Intensidad):
        raise ValueError("La intensidad debe ser un valor de Intensidad.")
    self._intensidad = valor

3.8 DOCUMENTACION Y NOMBRES CLAROS
Los nombres de clases, métodos y atributos son descriptivos y en
español (o inglés) claro.

Se han añadido docstrings en las clases y métodos principales.

Se usan comentarios para explicar secciones complejas.
