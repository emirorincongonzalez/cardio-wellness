1. INTRODUCCIÓN
----------------------------------------------------------------
La capa de servicios constituye el conjunto de utilidades y
orquestadores que complementan la lógica de negocio del sistema.
Su responsabilidad es proporcionar funcionalidades transversales
que no pertenecen estrictamente al dominio, a la persistencia o
al control, pero que son esenciales para el funcionamiento de la
aplicación.

Esta capa se divide en tres servicios principales:
1. GestorSeguridad: Manejo de hashing y verificación de contraseñas.
2. GeneradorReportesPDF: Generación de reportes en formato PDF.
3. SistemaWellness: Orquestación de alto nivel para sugerencias,
   cálculos y reportes.

Todos estos servicios están disponibles en la carpeta `src/servicios/`
y se consideran definitivos. Están alineados con el DCD y con los
requisitos de auditoría (LOG de actividades, parámetro META).

2.1 GESTORSEGURIDAD (gestor_seguridad.py)
----------------------------------------------------------------
Propósito: Garantizar la seguridad de las contraseñas mediante
el uso de bcrypt, un algoritmo de hashing adaptativo.

CARACTERÍSTICAS DESTACADAS:
- ✅ Configuración del factor de costo (ROUNDS) desde variables
  de entorno (BCRYPT_ROUNDS / ROUNDS), con fallback a 12.
- ✅ Generación de hash con salt aleatorio.
- ✅ Verificación de contraseñas contra hash almacenado.
- ✅ Validaciones robustas de entrada (contraseña vacía, tipos
  incorrectos).
- ✅ Logging de advertencias y errores (para auditoría).
- ✅ Manejo de excepciones para evitar fallos en la verificación.

APLICACIÓN EN EL CÓDIGO:
```python
class GestorSeguridad:
    @staticmethod
    def generar_hash(contrasenia: str) -> str:
        # Genera hash bcrypt con rounds configurable
        rounds = GestorSeguridad._obtener_rounds()
        return bcrypt.hashpw(
            contrasenia.encode("utf-8"),
            bcrypt.gensalt(rounds=rounds)
        ).decode("utf-8")

    @staticmethod
    def verificar_contrasenia(contrasenia: str, hash_guardado: str) -> bool:
        # Verifica la contraseña contra el hash almacenado
        return bcrypt.checkpw(
            contrasenia.encode("utf-8"),
            hash_guardado.encode("utf-8")
        )

USO EN EL SISTEMA:

    UsuarioDAO.guardar() usa generar_hash() para hashear la
    contraseña antes de guardarla.

    UsuarioDAO.iniciar_sesion() usa verificar_contrasenia() para
    validar credenciales.

    ControlAutenticacion delega en el DAO para la verificación.

2.2 GENERADORREPORTESPDF (generador_reportes_pdf.py)
----------------------------------------------------------------
Propósito: Generar reportes de progreso en formato PDF para los
clientes, cumpliendo con el requisito de auditoría y proporcionando
una salida visual y profesional.

CARACTERÍSTICAS DESTACADAS:

    ✅ Usa la biblioteca reportlab para crear PDFs.

    ✅ Estructura clara: título, datos del cliente, resumen de
    actividad, historial mensual.

    ✅ Estilos visuales atractivos (colores, tablas, negritas).

    ✅ Flexibilidad para guardar en una ruta específica o en una
    carpeta por defecto (reportes/).

    ✅ Adaptado para trabajar con objetos ProgresoMensual en lugar
    de diccionarios (corrección realizada).

    ✅ Muestra el mes en formato legible (ej. "Septiembre 2026").

APLICACIÓN EN EL CÓDIGO (adaptación a objetos del dominio):
# Antes: historial_progreso era lista de diccionarios
# Ahora: historial_progreso es List[ProgresoMensual]

def calcular_diferencia_peso_mensual(self, id_cliente: int) -> Decimal:
    historial = self.control_progreso.consultar_progreso(id_cliente)
    if len(historial) < 2:
        return Decimal("0.0")
    reg_actual = historial[0]   # ProgresoMensual más reciente
    reg_anterior = historial[1] # ProgresoMensual anterior
    return reg_actual.peso - reg_anterior.peso

3. BUENAS PRÁCTICAS APLICADAS
----------------------------------------------------------------
3.1 PRINCIPIO DE RESPONSABILIDAD ÚNICA (SRP)

    Cada servicio tiene una responsabilidad clara y bien definida.

    GestorSeguridad solo maneja hashing y verificación.

    GeneradorReportesPDF solo genera PDFs.

    SistemaWellness orquesta funcionalidades de alto nivel.

3.2 INYECCIÓN DE DEPENDENCIAS

    Todos los servicios reciben sus dependencias en el constructor,
    facilitando pruebas unitarias y cambios futuros.

    Ejemplo: SistemaWellness recibe control_clientes, control_rutinas,
    etc., permitiendo reemplazar implementaciones si es necesario.

3.3 MANEJO DE EXCEPCIONES

    Los servicios capturan y registran errores sin ocultarlos.

    En SistemaWellness.emitir_reporte_pdf_cliente(), los errores
    se registran en el LOG y se relanzan como RuntimeError.

3.4 LOGGING Y AUDITORÍA

    Todos los servicios heredan de ControlBase para usar
    _registrar_log (en el caso de SistemaWellness).

    Se registran acciones como: SUGERENCIA_RUTINA, REPORTE_PDF_GENERADO,
    CALCULO_DIFERENCIA_PESO, etc.

    El LOG cumple con el formato FECHA, USUARIO, ACCION (requisito
    de Auditoría de Sistemas).

3.5 TYPE HINTS Y DOCSTRINGS

    Todos los métodos y clases están tipados y documentados.

    Esto mejora la legibilidad y el autocompletado en el IDE.

3.6 USO DE DECIMAL PARA CÁLCULOS FINANCIEROS/MÉTRICAS

    En calcular_diferencia_peso_mensual, se usa Decimal para
    evitar errores de redondeo en cálculos con decimales.

4. CONCURRENCIA CON EL DCD Y EL DDL
----------------------------------------------------------------
Los servicios no tienen una representación directa en el DCD
(no son clases del dominio), pero están alineados con las
necesidades del sistema y con los requisitos de auditoría.

RELACIÓN CON EL DCD:

    GestorSeguridad: No está en el DCD, pero es una utilidad
    necesaria para la seguridad (requisito no funcional).

    GeneradorReportesPDF: Tampoco está en el DCD, pero es un
    servicio de salida para reportes (requisito funcional).

    SistemaWellness: Orquesta controladores del DCD (ControlClientes,
    ControlRutinas, ControlProgreso) y proporciona funcionalidades
    como sugerencia de rutinas y cálculo de diferencia de peso.
